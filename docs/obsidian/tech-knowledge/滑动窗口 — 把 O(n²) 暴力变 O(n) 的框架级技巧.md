# 滑动窗口 — 把 O(n²) 暴力变 O(n) 的框架级技巧

> [!abstract]
> **滑动窗口 (Sliding Window)** 是一种把「枚举所有子数组 / 子串」从 $O(n^2)$ 降到 $O(n)$ 的框架级技巧。它不是单个算法，而是一套识别问题结构、维护区间状态、单调移动边界的思维模型。

## 1. 一句话理解

如果一个问题要求你在数组或字符串里找一段连续区间，并且区间右端扩张、左端收缩时答案状态可以被增量维护，那么它很可能适合滑动窗口。

把暴力法想象成：

```text
每次都重新框一段区间 → 从头计算区间信息 → 再换下一段
```

滑动窗口想象成：

```text
窗口向右滑动 → 新元素进来 → 旧元素出去 → 状态局部更新
```

核心差别是：**暴力法反复计算重叠区间；滑动窗口复用重叠区间的信息。**

## 2. 从 O(n²) 暴力开始：问题出在哪里？

以「找满足条件的连续子数组 / 子串」为例，暴力枚举通常是：

```text
for left in 0..n-1:
    for right in left..n-1:
        检查 nums[left..right]
```

它慢的原因不是双层循环本身，而是它把大量高度重叠的区间当成彼此独立：

```text
[0..2] = a b c
[0..3] = a b c d   ← 只多了 d，却可能重新算 a b c d
[1..3] =   b c d   ← 只少了 a，却可能重新算 b c d
```

滑动窗口的关键洞察是：连续区间之间有天然的增量关系。

```text
窗口状态 S(left, right)
  + 加入 nums[right+1]
  - 移除 nums[left]
  = 下一个窗口状态
```

只要状态能被增量维护，复杂度就有机会从「枚举区间数量」降到「每个元素进出一次」。

## 3. 滑动窗口的本质：两个边界 + 一个可维护状态

滑动窗口由三部分组成：

| 组件 | 含义 | 典型变量 |
|---|---|---|
| 左边界 | 当前区间起点 | `left` |
| 右边界 | 当前区间终点 | `right` |
| 窗口状态 | 当前区间内的统计信息 | `sum`、`countMap`、`maxFreq`、`distinct` |

结构图如下：

```text
数组 / 字符串：
index:  0   1   2   3   4   5   6
value:  a   b   c   d   e   f   g
              └──── window ────┘
             left            right

状态：窗口内频次、总和、不同字符数、最大频次等
```

滑动过程：

```text
1. right 向右扩张：把新元素加入窗口
2. 判断窗口是否违反约束
3. 如果违反，left 向右收缩：把旧元素移出窗口
4. 在合法窗口上更新答案
```

## 4. 为什么它能变成 O(n)？

很多人看到滑动窗口里也有 `while`，会担心它还是 $O(n^2)$：

```text
for right in range(n):
    while window_invalid:
        left += 1
```

真正的复杂度不是「for × while」，而是看指针移动次数：

- `right` 从 0 到 n-1，只走 n 次；
- `left` 也只会从 0 到 n-1，最多走 n 次；
- 每个元素最多进入窗口一次、离开窗口一次。

因此总操作数是：

$$
O(n) + O(n) = O(n)
$$

直观图：

```text
right: 0 → 1 → 2 → 3 → ... → n-1
left : 0 → 1 → 2 → 3 → ... → n-1

两个指针都只向右，不回头。
```

这就是滑动窗口的复杂度奥义：**不是没有嵌套循环，而是内层循环的总次数被全局摊还了。**

## 5. 固定窗口 vs 可变窗口

滑动窗口常见两大类。

### 5.1 固定长度窗口

问题特征：窗口大小固定为 `k`。

典型问题：

- 长度为 `k` 的子数组最大和；
- 长度为 `k` 的平均值；
- 长度为 `k` 的字符串是否满足某种频次条件。

框架：

```text
先加入 right 元素
如果窗口长度超过 k：移除 left 元素，left++
如果窗口长度等于 k：更新答案
```

示意：

```text
k = 3
[a b c] d e f   → 统计 a+b+c
 a [b c d] e f  → 移除 a，加入 d
 a b [c d e] f  → 移除 b，加入 e
```

固定窗口的核心是：**每次窗口大小保持不变，状态只做一进一出。**

### 5.2 可变长度窗口

问题特征：窗口大小不固定，需要满足某个约束。

典型问题：

- 和至少为 `target` 的最短子数组；
- 最多包含 `k` 个不同字符的最长子串；
- 不含重复字符的最长子串；
- 覆盖目标字符集合的最小窗口。

框架：

```text
for right in 0..n-1:
    加入 nums[right]

    while 窗口违反约束 或 已经满足并尝试优化:
        更新答案（取决于题型）
        移除 nums[left]
        left++
```

可变窗口的难点在于：**什么时候收缩，以及收缩前还是收缩后更新答案。**

## 6. 两类核心题型：最长合法 vs 最短满足

滑动窗口最容易混淆的地方是答案更新时机。可以先按目标分成两类。

### 6.1 找「最长合法窗口」

目标：窗口必须始终满足约束，尽可能长。

例子：最长不含重复字符的子串。

策略：

```text
right 扩张后，如果窗口非法，就收缩到合法
窗口合法后，更新最大长度
```

框架：

```text
for right in range(n):
    add(s[right])

    while invalid(window):
        remove(s[left])
        left += 1

    ans = max(ans, right - left + 1)
```

关键点：更新答案时，窗口已经合法。

### 6.2 找「最短满足窗口」

目标：窗口一旦满足条件，就尽量缩短。

例子：和至少为 `target` 的最短子数组、最小覆盖子串。

策略：

```text
right 扩张直到窗口满足条件
一旦满足，就在 while 中不断收缩并更新最小答案
```

框架：

```text
for right in range(n):
    add(nums[right])

    while valid(window):
        ans = min(ans, right - left + 1)
        remove(nums[left])
        left += 1
```

关键点：更新答案时，窗口正处于满足条件的状态；之后再收缩，尝试更短。

## 7. 判断一道题能不能用滑动窗口

可以用这张检查表：

| 判断问题 | 如果答案是「是」 | 含义 |
|---|---|---|
| 是否处理连续子数组 / 子串？ | 是 | 滑动窗口候选 |
| 窗口状态能否增量维护？ | 是 | 可以避免重复计算 |
| 左右边界是否都只需单调向右？ | 是 | 具备 $O(n)$ 可能 |
| 约束是否具有可收缩性？ | 是 | 可变窗口成立 |

最重要的是第四点。

所谓「可收缩性」是指：当窗口不满足或已经满足某种条件时，移动左边界能朝着目标方向推进，而不是让状态变得不可预测。

例如：

- 正数数组中，窗口和太大，左边界右移会让和变小；
- 字符串中，重复字符太多，左边界右移会减少频次；
- 不同字符数超过 `k`，左边界右移可能减少不同字符数。

但如果数组含有负数，「窗口和随着右扩张变大、左收缩变小」这个单调性就可能失效，此时很多求和类滑动窗口会失效，可能需要前缀和 + 哈希表、单调队列等方法。

> [!warning]
> 滑动窗口不是看到「子数组」就能用。关键是：窗口合法性或优化方向必须能通过单调移动边界维护。

## 8. 经典模板：固定窗口

以「长度为 k 的子数组最大和」为例：

```java
int maxSumOfSizeK(int[] nums, int k) {
    int sum = 0;
    int ans = Integer.MIN_VALUE;

    for (int right = 0; right < nums.length; right++) {
        sum += nums[right];

        if (right >= k) {
            sum -= nums[right - k];
        }

        if (right >= k - 1) {
            ans = Math.max(ans, sum);
        }
    }

    return ans;
}
```

这里没有显式 `left`，因为固定窗口的左边界可以由 `right - k + 1` 推出。

## 9. 经典模板：最长不重复子串

题意：给定字符串，找不含重复字符的最长子串长度。

状态：字符频次 `freq`。

```java
int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> freq = new HashMap<>();
    int left = 0;
    int ans = 0;

    for (int right = 0; right < s.length(); right++) {
        char in = s.charAt(right);
        freq.put(in, freq.getOrDefault(in, 0) + 1);

        while (freq.get(in) > 1) {
            char out = s.charAt(left);
            freq.put(out, freq.get(out) - 1);
            left++;
        }

        ans = Math.max(ans, right - left + 1);
    }

    return ans;
}
```

为什么 `while (freq.get(in) > 1)` 就够？因为只有新加入的字符 `in` 可能让窗口从合法变成非法；其他字符在加入前已经合法。

## 10. 经典模板：和至少为 target 的最短子数组

题意：正整数数组中，找到和至少为 `target` 的最短连续子数组长度。

状态：窗口和 `sum`。

```java
int minSubArrayLen(int target, int[] nums) {
    int left = 0;
    int sum = 0;
    int ans = Integer.MAX_VALUE;

    for (int right = 0; right < nums.length; right++) {
        sum += nums[right];

        while (sum >= target) {
            ans = Math.min(ans, right - left + 1);
            sum -= nums[left];
            left++;
        }
    }

    return ans == Integer.MAX_VALUE ? 0 : ans;
}
```

注意前提：`nums` 必须是正整数或至少非负且满足单调收缩语义。若存在负数，`sum >= target` 后收缩不一定安全。

## 11. 滑动窗口常见状态设计

| 问题类型 | 状态变量 | 合法性判断 |
|---|---|---|
| 固定长度最大和 | `sum` | `right - left + 1 == k` |
| 不含重复字符 | `freq` | 所有字符频次 ≤ 1 |
| 最多 k 个不同字符 | `freq` + `distinct` | `distinct <= k` |
| 覆盖目标字符串 | `windowFreq` + `needFreq` + `formed` | `formed == required` |
| 替换后最长重复字符 | `freq` + `maxFreq` | `windowLen - maxFreq <= k` |

设计状态时要问：

1. 新元素进入窗口时，哪些统计量要更新？
2. 旧元素离开窗口时，哪些统计量要回滚？
3. 是否能 $O(1)$ 判断窗口是否合法？
4. 答案应该在窗口合法时更新，还是满足后收缩前更新？

## 12. 容易踩坑的地方

### 12.1 `while` 和 `if` 的选择

可变窗口通常用 `while`，因为一次扩张可能需要多次收缩才能恢复合法。

```text
right 加入一个元素后：
窗口可能从「刚好合法」变成「严重非法」
需要 left 连续移动多次
```

### 12.2 更新答案的时机

- 最长合法：先收缩到合法，再更新最大值；
- 最短满足：在满足状态下先更新最小值，再尝试收缩。

### 12.3 忘记维护离开元素

如果使用频次表，移出元素时要减少计数；计数为 0 时，有时还要删除 key 或减少 `distinct`。

### 12.4 负数破坏求和窗口

「正数数组求最短 / 最长和」常可用滑动窗口；含负数时要谨慎，因为窗口和不再随边界单调变化。

### 12.5 `maxFreq` 是否需要回退

在「替换后最长重复字符」一类题中，`maxFreq` 常可以不回退，因为它作为历史最大频次只影响是否延迟收缩，不会导致最终答案变大到错误。但这个技巧依赖具体题型，不要机械套用。

## 13. 和双指针的关系

滑动窗口是双指针 (Two Pointers) 的一个特殊分支。

```text
双指针
├─ 对撞指针：left 从左、right 从右向中间靠拢
│  └─ 典型：两数之和 II、盛最多水的容器
└─ 同向指针：left 和 right 都向右移动
   └─ 滑动窗口：维护一个连续区间及其状态
```

滑动窗口的特色在于：它不仅移动两个指针，还维护窗口内的聚合状态。

## 14. 思维框架：四步落地法

遇到疑似滑动窗口题，可以按以下步骤解：

```text
第一步：定义窗口
  窗口代表什么？是子数组、子串，还是某段时间区间？

第二步：定义状态
  窗口内需要维护什么？sum、freq、distinct、formed？

第三步：定义合法性
  什么时候窗口合法？什么时候必须收缩？

第四步：定义答案更新时机
  合法后更新最大？满足时更新最小？固定长度时更新？
```

简化成一句模板：

```text
right 负责探索新可能，left 负责丢弃不可能，state 负责让每次判断 O(1)。
```

## 15. 练习路线

建议按难度递进：

1. 固定窗口最大和；
2. 长度为 k 的平均值；
3. 最长不含重复字符的子串；
4. 最多包含 k 个不同字符的最长子串；
5. 和至少为 target 的最短子数组；
6. 最小覆盖子串；
7. 字符替换后的最长重复字符；
8. 带负数约束时，比较滑动窗口、前缀和、单调队列的边界。

## 16. 总结

滑动窗口把 $O(n^2)$ 暴力变成 $O(n)$，靠的不是魔法，而是三个条件：

1. 问题围绕连续区间；
2. 区间状态可以增量维护；
3. 左右边界能单调推进。

它的框架价值在于：一旦识别出「窗口 + 状态 + 合法性 + 更新时机」，大量子数组 / 子串题都会变成同一种模式。

> [!tip]
> 学滑动窗口，不要背题解。要训练自己不断问四个问题：窗口是什么？状态是什么？何时收缩？何时更新答案？
